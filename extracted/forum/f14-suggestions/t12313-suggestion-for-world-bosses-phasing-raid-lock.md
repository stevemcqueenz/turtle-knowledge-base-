## Post 82266 by Imonobor (Bug Report Enthusiast) — 2023-12-22T09:10:00Z
<!-- url: https://forum.turtlecraft.gg/viewtopic.php?p=82266#p82266 | page 1 | era: pre-1.18.1 -->

Yeah, big no for the phasing, but the "lockout" idea could be worked on.

When a raid kills a world boss, they could get an ID that prevents them from being able to loot or receive loot via ML from that boss again for the duration. Such a system would be quite exploitable, so a lot of thought should be put into it to prevent that. Also it might be quite hard to code, but I'm not a dev so I wouldn't know.

For example, a guild could "sell" world boss loot by including the buyer(s) and a non-locked guildie that would be the loot master, while the core raiders could be locked without a problem, so it wouldn't help with the current situation of world bosses being farmed.

To fix this, maybe when engaging a world boss, people who don't have an ID and are in range should get a prompt to leave the raid or get the same ID as the rest. On a kill, the game would check if anyone in the raid has an ID, and if they do, it will give the same ID to everyone without an ID, so the boss will be unlootable. Anyone invited after the kill will also be unable to loot it.

But then there is the next exploit: a single person or a small raid without an ID could "tag" the boss, while a core ID-locked raid could do the actual killing.
To counter this the raid that did the most damage to the boss should get the loot?

Dunno I'm just brainstorming here, it's quite a complex thing to work around. Share your thoughts too.   smiling_turtle
